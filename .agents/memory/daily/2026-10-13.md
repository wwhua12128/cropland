# 2026-10-13 插件被卸载后装回（花花操作，AI 代做）

第三人称事件日志（写给没有共同历史的未来读者）。

## 事件
- 花花遇到上一轮 metadata.txt BOM 导致的"插件破损"，遂在 QGIS 插件管理器里
  **卸载**了 Cropland Delineator，准备重装。
- 卸载的实际后果（值得记住）：QGIS 删掉了 `plugins\cropland_delineator`
  **联接目录本身**（联接目标=工作区源码，未受损），并删掉了 `QGIS4.ini`
  `[PythonPlugins]` 里的 `cropland_delineator=true`；`[cropland_delineator]`
  段的 `nn_dir` 等设置保留。

## 处置
1. 旧实体副本 `cropland_delineator_v089_bak`（实为 0.10.1，显示名与主线**完全同名**）
   移出扫描路径 → `profiles\default\python\_archive_plugins\`，避免两条同名插件
   在注册表里撞成 `cropland_delineator-0`。
2. 重建联接 → 工作区 `cropland\qgis-plugin\cropland_delineator`（版本 0.10.2）。
3. QGIS 关闭状态下改写 `QGIS4.ini`：`[PythonPlugins]` 补 `cropland_delineator=true`，
   写前备份 `QGIS4.ini.bak-20261013-185842`，写后校验无 BOM（首 3 字节 91,71,101）。

## 验收
- `configparser` 读 metadata.txt：version=0.10.2，name 正常（非 BOM）。
- 10 个 .py 全部 `py_compile` 通过。
- QGIS 自带解释器从 profile 路径 `import cropland_delineator` → `classFactory` 可调用。
- nn 解释器 `D:\software\cropland\nn\.venv`：python 3.12.10 / torch 2.6.0+cu124 /
  cuda_available True（与 ini 里 nn_dir 一致）。

## 教训
- **PS 5.1 读 UTF-8 无 BOM 的 .ps1 会按 ANSI 解码**，中文脚本直接 ParserError
  （与 `Set-Content -Encoding utf8` 写 BOM 是同一个坑的两面）：临时 .ps1 一律写
  纯 ASCII，或用 pwsh 7 执行。
- 改 `QGIS4.ini` 必须在 QGIS 关闭时做，否则退出时被内存态覆盖。
